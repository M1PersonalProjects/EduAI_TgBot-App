# EduAI TZ29 — natural tutor, Teacher/Student UI, interactive assignments

Пакет рассчитан на актуальный `main` репозитория `M1PersonalProjects/EduAI_TgBot-App` по состоянию на 2026-08-14.

## Что меняется

- Один базовый англоязычный prompt ИИ-тьютора + небольшие role/context/task blocks.
- Обычный разговор больше не блокируется как «неучебный».
- Школа + СПО/колледж + университет.
- Book Mode остаётся главным выбранным источником, но может дополняться внешними знаниями/поиском, когда материала мало, он явно не покрывает вопрос или пользователь просит актуальную проверку. Если учебный запрос не найден в локальных материалах, web-search может использоваться как fallback; обычный разговор не запускает поиск автоматически.
- WebApp и Telegram продолжают использовать общий `services.tutor.respond()`.
- Вложения анализируются до permissive scope guard; пустой caption сам по себе не является отказом.
- Технические роли НЕ меняются: `parent | student | admin`; Admin по-прежнему может открыть режим Учителя, а ИИ интерпретирует этот режим как Teacher без изменения роли в БД.
- Пользовательские названия: `Учитель | Ученик | Администратор`.
- В генераторе заданий Учителя учебник больше не обязателен на frontend/backend: при выборе он остаётся основным источником.
- Интерактивные HTML-задания: создание из чата, редактирование с версиями, карточка в истории, безопасный preview, самодостаточный HTML download, назначение Ученику, сохранение результата через существующие `tasks_history` / `task_submissions`. Скачанный HTML содержит собственный UI/результат и не зависит от bridge EduAI для основной работы.
- Telegram получает финальный raw-LaTeX firewall, включая старые canonical сообщения и TeX, случайно попавший в code span.
- Mobile tutor layout убирает лишнюю цепочку `100dvh`/вложенных scroll containers только для секций чата.
- Старый pytest-тест, требующий `migrations/028_conversation_context.sql`, удаляется. Папка `migrations/` для pytest не нужна.

## Установка

1. Остановите EduAI.
2. Распакуйте ZIP в корень проекта с сохранением структуры.
3. Запустите безопасный staged installer:

```bash
python3 apply_tz29_safe.py
```

`apply_tz29_safe.py` сначала копирует текущие `api/`, `bot/`, `services/`, `static/`, `templates/`, `tests/` и нужные конфиги во временную staging-копию, затем применяет patch, запускает verifier, Python compile, `node --check` (если Node установлен) и **полный `pytest -q`**. Если любой шаг не проходит, реальные файлы проекта не изменяются. Только после успешной проверки создаётся backup `.tz29_backup_safe` и изменения атомарно копируются в проект.

4. В DataGrip выполните файл из корня архива:

```text
TZ29_interactive_apps.sql
```

SQL создаёт только таблицы интерактивных приложений. Он **не меняет** enum/значения ролей и связи `parent ↔ student`.

5. Проверка:

```bash
python3 verify_tz29.py
python3 -m compileall -q api bot services tests main.py
node --check static/js/app.js
node --check static/js/chat.js
node --check static/js/interactive.js
python3 -m pytest -q
```

6. Запустите проект:

```bash
python3 main.py
```

После обновления frontend сделайте hard refresh (`Cmd + Shift + R`) и перезапустите Telegram WebApp.

## Быстрые ручные проверки

- Student: `Как у тебя дела?` — нормальный разговор без образовательного отказа.
- Student: `Что ты умеешь?` — нормальное описание возможностей EduAI.
- Student: отправить фото учебного задания без подписи — сначала анализ фото.
- Book Mode: выбрать учебник с коротким фрагментом и попросить более подробное объяснение — книга остаётся primary source, но ответ не отказывается из-за нехватки текста.
- Book Mode → обычный разговор → новый учебный вопрос — без создания нового чата и без старого attachment bleed.
- Telegram: ответы с `\\frac`, `\\sqrt`, `\\times`, `\\text`, `\\begin{cases}` не показывают сырой LaTeX.
- Teacher: `Создай интерактивный тест по дробям на 10 вопросов` — появляется карточка с Open / Edit / Download / Assign.
- После `Добавь ещё 5 вопросов` версия увеличивается, исходная версия остаётся в `interactive_app_versions`.
- Teacher назначает приложение Ученику; Student открывает его в обычном списке заданий, а результат попадает в `task_submissions`.
- На iPhone/Android/Telegram WebApp после поля ввода нет большого пустого вертикального хвоста.

## Важно про роли

Внутренний контракт остаётся прежним:

```text
DB / backend / API / permission checks:
parent | student | admin

UI / Telegram / prompts:
Учитель | Ученик | Администратор
```

Не выполняйте миграцию `parent -> teacher`.
